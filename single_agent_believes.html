Single agent · belief

Planning for what one agent believes

A robot that commands a door it cannot see. One oblivious ontic action is enough to detach a single agent’s picture of the world from the world, which takes the frame out of \(\mathrm{S5}\) with nobody else involved at all.

The four cases

Two axes: how many agents, and knowledge or belief

Adding an agent indexes the modality. Dropping the truth axiom turns knowledge into belief. The four pages below are the four combinations, each with a domain that reaches it.

Planning for what one agent knows \(\mathrm{S5}\) · lone-inspector Sensing refines one partition. Nothing is hidden, because there is nobody to hide it from. Planning for what one agent believes \(\mathrm{KD45}\) · remote-door The world changes while the agent is not looking, and its picture of the world stops matching it. Planning for what a fleet knows \(\mathrm{S5}_n\) · ugv-coordination Four observability models over one facility, and what each one costs to plan. Planning for what a fleet believes \(\mathrm{KD45}_n\) · hotel-incident One agent is told and another is not, so the fleet stops agreeing about what is the case.

The planning task

Dropping one axiom, and what it costs

\(\mathrm{S5}\) is \(\mathrm{KT45}\). Removing T and putting D in its place gives \(\mathrm{KD45}\), the logic of belief. The modality is written \(B\), and the axioms are:

K
\(B(\varphi \to \psi) \to (B\varphi \to B\psi)\) holds on every frame
D
\(B\varphi \to \neg B\neg\varphi\) \(R\) serial: belief is consistent, and may be false
4
\(B\varphi \to BB\varphi\) \(R\) transitive
5
\(\neg B\varphi \to B\neg B\varphi\) \(R\) Euclidean

Without reflexivity the world that is the case need not lie in the agent's own accessible set, so \(B\varphi \wedge \neg\varphi\) becomes satisfiable. The agent remains consistent and fully introspective about a belief that is wrong, which is what makes the failure worth planning against: nothing inside the agent's perspective reveals it.

With a single agent there is nobody to hide anything from, so the usual multi-agent route to false belief is closed. What remains is an action the agent performs without observing its effect. That is enough.

The domain

remote-door: commanding what you cannot see

A robot in the office, a door in the plant, and a command that shuts the door remotely. The robot issues the command and cannot see the result. The action is ontic and the only agent is oblivious to it: 

(:action command-shut
  :parameters (?i - agent ?z - zone)
  :action-type (private-ontic (e-command ?i ?z) (nil))
  :observability-conditions (default Oblivious))

The alternative event is nil, so after the update the agent still relates to a copy of the world in which nothing happened, and that copy is the one it takes itself to be in. The door is shut; the agent believes it open. The parser reports the frame accordingly.

Going to the plant and looking is the repair. It is a sensing action with one designated event per reading, and standing at the door makes the readings distinguishable: 

(:action look
  :parameters (?i - agent ?z - zone)
  :action-type (public-sensing (e-look-shut ?i ?z) (e-look-open ?i ?z))
  :observability-conditions (default Fully))

The first row is the result this page exists to show. The declaration alone is enough for the parser to classify the task as \(\mathrm{KD45}\): a single-agent domain with one oblivious ontic action leaves the frame non-reflexive, and belief becomes the attitude the planner reasons about.

Shutting the door takes one action. Coming to know it is shut does not currently reach a solution: the search reports its space exhausted at depth three, below the length of the plan that ought to work (command, drive, look). The repair path is stated in the domain and the goal is expressible, so the gap is in the search rather than the modelling. It is recorded here as an open item.

Reproduction

Running it

cd epddl-workspace/remote-door
plank export -d remote-door.epddl -p instances/problem_1.epddl \
      -l $PLANK/benchmarks/libraries/intermediate.epddl -o out
epistemic_planner --task out/problem_1.json --plan out/problem_1-plan.json

The parser prints its frame verdict on the first line, which is where \(\mathrm{KD45}\) in the table above comes from.
